feat(validate): read BMP, add a factory image check, and make runs reproducible

Validation against the 17 real BMP frames in D:\FTP\patmax surfaced four things worth
fixing, plus one thing worth writing down.

- BMP support. The validation sets on this machine are raw 8-bit indexed BMP dumps, and the
  loader only understood PNG. Core/BmpReader handles 1/4/8-bit indexed and 16/24/32-bit
  BI_RGB, bottom-up or top-down; Core/ImageLoader dispatches on the file signature and sorts
  a folder naturally so "2" comes before "10".
- Reproducibility. Candidates were collected from a ConcurrentBag and sorted on score alone,
  so ties kept whatever order the parallel workers finished in: the same image could report
  0.895 or 0.562 at two different poses depending on thread timing. Hypotheses now sort on
  (score, |angle|, angle, X, Y, scale); 16 of the 17 frames are bit-identical run to run, and
  the remaining one is a near-black frame whose scores are noise.
- Candidate selection. The coarse stage filled angle buckets and silently dropped the
  strongest hypothesis once its bucket was full. The top half by score is now guaranteed a
  slot and bucket diversity only fills the rest.
- IgnorePolarity was wrong. It set the feature polarity to +1 while leaving a normal that had
  already been flipped, so half of the responses went negative and every image scored ~0.45.
  The model now carries PolarityAgnostic and the scoring compares |directional response|; the
  inverted-contrast frame goes from 0.639 to 0.917. It stays off by default because ignoring
  polarity costs discrimination (2.bmp drops from 1.000 to 0.674).
- Automatic edge threshold. A fixed absolute floor loses most edges of an underexposed frame.
  The floor is now min(NoiseFloor, max(3 x median, 10% x p99)), so it only comes down when
  even the strongest edges are weak - a mostly black frame with one bright part keeps the
  fixed floor instead of dropping into compression noise.
- Normalised correlation is implemented and off by default: it is a wash on this data (fixes
  a dim frame, breaks a part seen through plastic bags).

The calibration report now prints score bands instead of a stability verdict, because a pose
sweep has no stable pose to measure, and it prints the edge floor actually used.

Measured: synthetic gate 10/10; D:\FTP\calibration 12/12 (11 at score 1.000, the twelfth is a
part clipped by the frame); D:\FTP\patmax 17/17 with 8 frames at score >= 0.90, 2 in
0.70-0.90 and 7 below 0.70, whose per-image causes (black frame, backlit, structured clutter,
multiple parts) are listed in the README rather than hidden.
