fix(ui): decode any bitmap format, add the training panel, and settle the canvas geometry

Reported from a manual session: training a box over the part failed with "0 edge features",
and the UI had no training parameters.

Training failure, root cause: ToGray copied pixels straight out of the WPF source assuming
4 bytes per pixel. That holds for Bgra32/Pbgra32 only; every BMP in the capture set is
8-bit indexed, so the whole frame came back shifted or black and any crop of it contained no
edges. Decoding through FormatConvertedBitmap(Bgra32) first fixes it; the same region now
trains 600 features and matches at score 1.000. The engine was never at fault: the CLI
trains the identical region fine with 21196 edge pixels.

Training parameters (the panel that was missing): algorithm label, IgnorePolarity,
AutoEdgeThreshold, EdgeThreshold, Grain, feature cap and minimum spacing. They are applied
when 训练模型 runs and the status line reports the edge threshold actually used.

Canvas geometry: the bitmap is now the canvas background (an ImageBrush) instead of a child
element, so canvas coordinates are image pixels by construction - no letterbox, no element
offset, no scaling transform. Region rectangles, markers and the feature overlay are all
positioned in image pixels and multiplied by Zoom on the way out. Verified deterministically
with `--show-region`, which draws a region given in image pixels: it lands exactly on the part.

Also:
- AcceptThreshold defaults to 0.7 instead of 0.5. On the 17-image set the frames that were
  matched wrongly scored 0.53-0.66 and are now rejected; the ten good frames score >= 0.75.
- `--probe <image> [x y w h]` prints crop size, edge pixels, effective floor and feature
  count for one region - the tool that found the decode bug.
- The viewer fits the whole image into the viewport, so the bottom of the frame is not clipped.
