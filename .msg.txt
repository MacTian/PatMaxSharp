feat(ui): batch and cycle a folder, and let the window record itself

Reviewing a capture set one image at a time through a file dialog is not a workable loop, so
the app can now take a folder:

- `--batch <folder>`   train on the first image, run every image, one row per image in the
                       results grid, and write patmax_batch_results.csv next to the images
                       (the grid only shows a handful of rows at a time).
- `--cycle <folder>`   walk the folder showing each image with its overlay, which is what the
                       per-image review actually needs.
- `--record <folder> <outDir>`  the same walk, but the window renders itself to PNG frames
                       after every match. Recording the desktop was unusable here: WeChat,
                       terminals and the editor keep stealing the foreground. Rendering the
                       visual tree is occlusion-proof and shows exactly what the canvas draws.
- `--batch` / `--cycle` / `--record` are also reachable from the UI (批量验证 button).

The cycle decodes with the image library rather than through the WPF bitmap, i.e. the same
path the batch and the CLI use; going through the WPF decode reported "0 results" for the
very image the batch matched at 1.000.

Layout: the results grid gets a real row with a GridSplitter, so a 17-image batch is not
clipped to one visible row.

Also moves the content-bounds helper into PatternTrainer so the UI and the CLI share it.
